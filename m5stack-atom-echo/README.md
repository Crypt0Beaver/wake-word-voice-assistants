# M5Stack Atom Echo Advanced Voice Assistant

An ESPHome configuration package for the M5Stack Atom Echo, transforming it into an ultra-responsive, state-aware local voice assistant. This project features local and remote wake word support, dynamic LED UI customization directly from Home Assistant, ambient noise filtering, and multi-room audio routing.

## ✨ Key Features

* **Dual Wake Word Engines:** Seamlessly switch between on-device `micro_wake_word` and Home Assistant continuous listening.


* **Dynamic LED UI:** Every state (Idle, Listening, Thinking, Speaking, Error, etc.) is exposed to Home Assistant as a virtual RGB light, allowing you to change colors and pulse effects on the fly without recompiling.


* **Advanced Audio Routing:** Play system sounds (beeps, errors, confirmations) locally on the device, route them to standard Home Assistant media players, or route them directly to Amazon Alexa devices using native cloud sounds.


* **Smart Ambient Noise Filter:** A custom STT parser automatically strips out background noise brackets generated by speech-to-text models (e.g., `[music]`, `(coughing)`) and aborts the pipeline if no actual speech is detected.


* **Conversation & Follow-up Modes:** Automatically keeps the microphone open if a question is detected in the TTS response.


* **Hardware Optimized:** Uses ESP-IDF with `SRAM1` mapped as instruction RAM for faster wake word processing, and disables WiFi power saving for minimal network latency.

## 🚀 Quick Start / Installation

To use this package, you do not need to copy the entire configuration. Instead, create a new node in ESPHome and reference the package directly from GitHub.

Here is a complete example of an instance configuration:

```yaml
# Check the readme for more information on how to use this package: https://crypt0beaver.github.io/wake-word-voice-assistants/m5stack-atom-echo/readme.md

substitutions:
  name: "atom-echo-instance"
  friendly_name: New Instance Atom Echo

  # Optional: Prevents having to enter settings in HA after a factory reset
  announcement_media_player_wav_default: media_player.living_room
  announcement_tts_target_default: notify.living_room_echo_speak
  notify_service_tts_default: notify.send_message

  # Optional: Override the following if you want to use local Home Assistant files instead of GitHub URLs
  # sounds_base_url: "http://url-to-your-sounds/"

packages:
  m5stack.atom-echo-voice-assistant: github://Crypt0Beaver/wake-word-voice-assistants/m5stack-atom-echo/m5stack-atom-echo.yaml@main

esphome:

# Override this to reduce the number of wake words loaded into memory or define custom ones. 
# This is highly recommended for ESP32 devices with limited memory.
micro_wake_word:
  models:
    - id: !remove okay_nabu
    - id: !remove hey_mycroft
    # - id: !remove hey_jarvis
    - model: "https://raw.githubusercontent.com/esphome/micro-wake-word-models/refs/heads/main/models/v2/experiments/choo_choo_homie.json"
      id: choo_choo_homie

api:
  encryption:
    key: "YOUR_ENCRYPTION_KEY_HERE"

logger:
    
wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

```

## ⚙️ Configuration & Home Assistant UI

Once flashed, this device will expose several entities to Home Assistant for real-time configuration:

### 🎛️ Settings (Configuration Entities)

* **Wake Word Engine Location:** A dropdown to switch between "On device" and "In Home Assistant".


* **Follow-up Mode & Conversation Mode:** Switches to dictate if the assistant should keep listening after speaking.


* **Audio Routing Switches:**
* `Enable response on local speaker`

* `Announce Wav on external media player`

* `Announce TTS on external media player`

* `Media player is an Alexa device`



* **Text Inputs:** Specify your external media players and TTS notify services directly in the HA UI.



### 💡 Virtual LED Customization

The package saves your LED preferences to flash memory after the first boot. You will see several RGB Light entities in Home Assistant, such as:

* `L. Idle Local Light`

* `L. Voice Listening Light`

* `L. Thinking Light`

* `L. Error Light`


Change the color, brightness, or apply a "Slow Pulse" or "Fast Pulse" effect to these virtual lights in Home Assistant, and the physical M5Stack LED will dynamically update whenever it enters that state.

## 🎵 Custom Sounds

By default, the package pulls `.wav` sound files from this GitHub repository for state changes (listening, error, confirm, etc.).

If your ESP32 experiences network lag fetching these files, it is highly recommended to host them locally on your Home Assistant server. To do this, uncomment and modify the substitution in your main yaml file:

```yaml
substitutions:
  sounds_base_url: "http://192.168.X.X:8123/local/sounds/"

```

## 🛠️ Hardware Button Actions

The physical button on the M5Stack Atom Echo is programmed with the following actions:

* **Short Press:** Starts the wake word/listening pipeline (or dismisses an active timer).


* **Long Press (10 seconds):** Triggers a complete factory reset of the device.
